# 开发与验证

## 0.1.1 远程发布修正

0.1.0 标签与归档保持原样。已实际读取其 JitPack status=ok 和远程 POM/GMM，发现：

- `com.github.gycrosskit:debug-tools` 是全模块聚合 POM，实际 KMP GMM 位于 `com.github.gycrosskit.debug-tools:debug-tools`。
- root metadataApiElements 与 metadataSourcesElements 被改写为同一普通 JAR URL，却分别声明 9492 和 10418 字节；实际下载为 9492 字节。
- iOS sources 与 native metadata 两个变体也被改写为同一普通 JAR URL，原本声明的 size/hash 不同。

因此 0.1.1 统一实际 JitPack group，复用组织模板定向删除这些已证实错误的 sources/native metadata 变体；
保留 common metadata、Android API/runtime AAR 和三个 iOS API KLIB。源码仍在 Git 标签中，IDE 自动 sources 变体不再发布。
每个版本使用独立 `build/maven/<版本>` staging，避免归档夹带旧坐标或旧版本。

0.1.1 macOS 归档发布成功，组织共用脚本在归档前修正规范化 metadata 并重算已有 MD5/SHA 校验文件。
实际核验 5 modules、11 variants、11 file/available-at refs，均存在且 size/hash 匹配；归档仅含 0.1.1。
归档 SHA-256：`d41e0dba69e4f9940c121c86e7da5ad2a69e5287da10bd3314407cac03692a1b`。
`bash -n`、`git diff --check` 和组织模板副本 `cmp` 通过。

## 本地检查入口

在组件根目录运行（Android SDK 由环境的 ANDROID_HOME 或本机未提交 local.properties 提供）：

```bash
bash gradlew --no-daemon --max-workers=2 \
  testDebugUnitTest iosSimulatorArm64Test publishAllPublicationsToStagingRepository
bash scripts/export-maven.sh
bash gradlew --no-daemon --max-workers=2 -p verification-consumer -I <临时staging脚本> \
  compileDebugKotlinAndroid compileKotlinIosArm64 compileKotlinIosX64 linkDebugFrameworkIosSimulatorArm64
```

宿主 Worktree 使用外部临时脚本为 debug-tools 及四个平台 artifact modules 精确注入 file Maven 仓库，
其他正式远程组件仍从其正常仓库解析；不保留 mavenLocal、includeBuild、宿主本地仓库属性或源码替代入口。

```bash
bash gradlew --no-daemon --max-workers=2 -Dorg.gradle.parallel=false -PcmpBrand=chonghe \
  -I <临时staging脚本> :app:testChongheDebugUnitTest --tests '*DebugToolsModuleTest' \
  :app:compileChongheQaKotlin :shared-ui:compileKotlinIosArm64 :shared-ui:compileKotlinIosX64 \
  :shared-ui:linkDebugFrameworkIosSimulatorArm64
python3 -m unittest ci.tests.test_affected_gradle_tests ci.tests.test_affected_ios_host_builds
```

首次组件构建缺少新目录的 SDK 配置，通过本次命令显式 ANDROID_HOME 后重跑成功。
临时依赖图检查脚本的语法和 root metadata/平台节点计数在开发中修正，最终核验通过；没有因此修改宿主构建规则。
